# Kikiyaku とローカル PLaMo 3 の接続実験

`kikiyaku_plamo.py` は、Kikiyaku の既定の翻訳リクエストを PLaMo 3 Translate の PFML3 形式へ変換する任意の補助ツールです。SoeYaku 本体には不要です。Python 3 の標準ライブラリだけを使います。

対象は [Kikiyaku `8dcc192`](https://github.com/utahta/kikiyaku/tree/8dcc192421937bf0fd632809f53899319b65eb37) の OpenAI 互換接続・既定システムプロンプト・英日翻訳です。Kikiyaku 本体の変更は不要です。システム指示に渡した用語集を除外する PLaMo の chat template を使う場合にも、用語と翻訳方向を直接モデルへ渡せます。

## 起動

[モデルの準備](../docs/model.md)を済ませ、SoeYaku リポジトリのルートでローカルモデルを起動します。空いているポートを選んでください。

```sh
Scripts/start-model.swift local/models/plamo-3-translate-2b-Q4_K_M.gguf 8090
```

モデルの起動が完了したら、別のターミナルで変換ツールを起動します。

```sh
python3 Tools/kikiyaku_plamo.py --port 8091 --backend-port 8090
```

Kikiyaku のプロファイルで次を指定します。

- 翻訳先: OpenAI 互換
- エンドポイント: `http://127.0.0.1:8091`
- API キー: 空欄
- モデル: このエンドポイントのモデル一覧に表示される名前
- 言語: 英語→日本語、または日本語→英語
- システムプロンプト: Kikiyaku の既定値
- 暫定翻訳: オフ

用語集は Kikiyaku の通常の用語集欄で指定します。SoeYaku の「Kikiyaku 用にコピー」から貼り付けられます。対応形式は `原語 = 訳語` またはタブ区切りです。

終了時は Kikiyaku の収音を停止し、変換ツールとモデルをそれぞれ Ctrl-C で止めます。片方を止めても、もう片方は自動終了しません。

## データと制約

両サーバーは `127.0.0.1` のみに待ち受けます。この例にはローカルプロセス間の認証はありません。既に API キーを使って起動したモデルへ接続する場合は、キーを環境変数 `LLAMA_API_KEY` に設定してから変換ツールを起動します。別の変数名は `--backend-key-env` で指定できます。キーを引数や文書へ書く必要はありません。

変換ツールは字幕本文・プロンプト・キーを保存しません。送信先は指定ポートの `127.0.0.1` に固定し、プロキシとリダイレクトを使いません。ブラウザの Origin 付き要求は拒否します。Kikiyaku 自体は停止時に原文と訳を保存するため、収音対象には別途注意が必要です。

英日以外、カスタムシステムプロンプト、ツール呼び出しには対応しません。現在の発話に現れる用語と、同じ翻訳方向の直近3対訳だけを渡します。逆方向では対訳の左右を交換します。反対方向の履歴は渡しません。

出力の上限は512トークンです。翻訳が未完了ならエラーを返し、途中の訳を成功として表示しません。SSE 接続は受け付けますが、完成した訳を一度に返すため、トークンごとの逐次表示はありません。要求は直列に処理します。認識誤りや翻訳品質そのものを補正する機能はありません。

## 検証

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Tests/AdapterTests -v
```

単体・HTTP テスト17件に加え、変更していない Kikiyaku の `OpenAICompatSession` と実モデルで、用語集の有無、履歴ありの英→日、日→英を確認しました。音声認識から字幕表示までの確認とは区別します。[検証記録](../docs/validation/kikiyaku-glossary-demo-2026-11-06.md)に結果と残件を記録しています。
