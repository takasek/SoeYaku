# SoeYaku

Mac で英語の PDF・HTML を読みながら、隣のウインドウで日本語訳を読むためのローカル翻訳ツールです。本文全体を先に PLaMo 3 Translate で訳して保存し、閲覧元でポインターを置いた文の訳を訳文ウインドウで強調して、その位置までスクロールします。PDF は「プレビュー」、HTML は選んだブラウザで読みます。翻訳と文字認識は Mac の中で行います。

講演を聴く用途には [Kikiyaku](https://github.com/utahta/kikiyaku) を使い、SoeYaku は配布資料などの文書を読む側を担います。両者は用語集の形式（`原語 = 訳語`）を揃えています。

画面の一部をその場で訳す枠モードもあります。枠1は訳を連続テキストとして、枠2は切り取った画像と原文位置の訳を一緒に表示します。どちらも全文の事前翻訳は不要です。

## 最初の訳を読む

Apple Silicon、macOS 26 以降、Swift 6.2 以降を含む Xcode、Homebrew 版の llama.cpp、Apple Development 署名を使います。

1. [モデルの準備](docs/model.md) に従って PLaMo 3 Translate 2B の GGUF を `local/models/` に置きます。
2. リポジトリのルートでアプリを作って開きます。画面収録の許可をアプリに結び付けておくため、ビルドには固定の署名を使います。

   ```sh
   Scripts/build-app.sh
   open dist/SoeYaku.app
   ```

3. 「PDF・HTML を開く…」で英語の文書を選ぶか、「URL を開く…」で公開ページの HTTP / HTTPS URL を入力します。PDF は「プレビューで開く」、HTML は閲覧するブラウザを選んで「ブラウザで開く」を押します。
4. 「全文を翻訳」を押します。訳した文から順に保存されるので、途中で中断しても次回は続きから訳します。翻訳サーバーはアプリが自動で開始・終了します。
5. 「プレビューに追従」または「ブラウザに追従」を押し、閲覧元で読みたい文にポインターを置きます。初回は「画面とシステムオーディオの録音」の許可を求められます。許可したら SoeYaku を開き直し、もう一度押してください。訳文ウインドウでその文の訳が強調され、スクロールやページ移動に合わせて移ります。

追従するのは閲覧元のアプリが最前面で、ポインターがその最前面ウインドウの中にあるときだけです。ポインターを訳文ウインドウへ移すと、訳文を自由にスクロールできます。閲覧元に戻すと追従を再開します。現在地を特定できないときは訳文ウインドウを動かさず、下端に「現在地を特定できません」と出します。

訳文は通常のウインドウとして扱い、常に最前面には固定しません。閲覧元を選ぶとその背面に回り、自動更新でも前面へ出ません。「ウインドウ」メニューの「操作ウインドウ」（`⌘1`）と「訳文ウインドウ」（`⌘2`）で窓を選べます。「訳文ウインドウ」ボタンも訳文を選択する操作です。訳文窓が閲覧元より前に重なっている場合は、その上のポインターで追従を休止します。背後の訳文窓は追従を妨げません。

プレビューでは選択した PDF と同じファイルを開いてください。異なるファイル名の文書や画像が前面の場合は追従を休止しますが、別ディレクトリの同名 PDF をファイル名だけでは区別できません。

HTML も同じ文書を選んだブラウザで開いてください。最前面の窓のタイトルが文書と異なる場合は追従を休止します。同じタイトルを持つ別ページの URL は区別できません。ブラウザの変更は追従を停止するので、変更後にもう一度開始してください。

## HTML の入力

保存した `.html`・`.htm`・`.xhtml`、または公開ページの URL を使えます。URL を開くときだけページをネットワークから取得します。取得にはブラウザの Cookie やログイン情報を使いません。HTML を解析するときに JavaScript を実行したり、画像・CSSなどのリンク先を読み込んだりすることはありません。翻訳は引き続きローカルで行います。

本文は `main`、単一の `article`、それらがなければ `body` から DOM 順に読み、見出し・段落・リスト・表の行を保ちます。ナビゲーション、スクリプト、フォーム、明示的な非表示要素は除きます。外部CSSによる非表示や並べ替え、JavaScriptだけで作られる本文には対応していません。ログインが必要なページや取得時と表示中で内容が変わるページは、本文を含むHTMLを保存して開いてください。HTML のサイズ上限は10 MBです。

HTML5の解析には [SwiftSoup 2.14.3](https://github.com/scinfu/SwiftSoup/tree/2.14.3) を使います。初回のビルド時にSwift Package Managerが取得し、バージョンとコミットは `Package.resolved` に固定しています。

## 用語集

共通の用語集と文書ごとの用語集を「共通の用語集…」「この文書の用語集…」でテキストエディタで開けます。1行に `原語 = 訳語`（Kikiyaku と同じ形式）または `原語<TAB>訳語` を書きます。文書の用語集が共通の用語集より優先され、英語の大文字と小文字は区別しません。用語集を変えたあと「全文を翻訳」を押すと、その用語を含む文だけを訳し直します。

「Kikiyaku 用にコピー」は、この文書に出現する用語だけを `原語 = 訳語` の1行1組でクリップボードに入れます。Kikiyaku の用語集欄にそのまま貼れます。

Kikiyaku からローカル PLaMo 3 Translate を使う場合は、両者で異なる原文・翻訳方向・用語集の送信形式を変換する[HTTPアダプタ](Tools/README.md)を用意しています。36秒の講演から認識した5発話と関連資料8文に、「子プロセス」「標準出力」が共通して現れました。[接続・実字幕・資料訳の記録](docs/validation/kikiyaku-glossary-demo-2026-11-06.md)に条件と制約を記録しています。

## 画面の一部を訳す

1. 操作窓で「枠1・テキスト」または「枠2・画像と訳」を選びます。
2. 「枠を選ぶ…」を押し、同じ画面の中で翻訳したい範囲をドラッグします。Escでキャンセルできます。
3. モデルを選び、「枠の翻訳を開始」を押します。英語の文字が変わると訳を更新します。

枠1は細長い選択範囲も使えます。訳は読み順の段落として並び、訳文窓の幅で折り返します。枠2は選択範囲の画像を別窓へ複製し、原文位置へ訳を重ねます。画像と訳は同じ比率で拡縮し、窓の縦横比も選んだ枠に揃えます。どちらの訳文窓も通常の前後順で扱います。

枠は画面上の位置に固定されます。元の窓を動かした場合は選び直してください。別の窓が重なると、その見えている内容も対象になるため、元の画面を見える位置に置いて使います。SoeYaku自身の窓は取り込みません。画面の画像・認識した原文・訳はファイルへ保存しません。同じ原文の訳は、開始してから停止するまでの間だけ再利用します。共通の用語集を使い、変更は停止して再開すると反映します。

同じ生成した台詞画面で、両モードの台詞更新と、枠2の絵・訳の同時縮小、文書表示への復帰を実機で確認しました。[枠モードの検証記録](docs/validation/frame-modes-2026-11-06.md)に条件と制約を記録しています。

## 保存するもの

`~/Library/Application Support/SoeYaku/` に共通の用語集を、その下の `Documents/<文書の SHA-256>/` に文書の用語集と訳文を保存します。訳文は原文・その文に適用した用語・モデルの組で引くので、同じ箇所に戻ると同じ訳が出ます。画面の画像と認識した文字は現在地を探すためにだけメモリ上で使い、保存しません。

モデルは GGUF の内容の SHA-256 で区別します。同じ名前でも内容の違うモデルの訳は再利用せず、同じ内容なら保存場所が変わっても再利用します。旧版のファイル名だけを使った保存項目は残しますが、新しい形式では訳し直します。

CLI でも同じ保存先を使えます。翻訳時は、起動済みのローカルサーバーのポートと、そのサーバーが使う GGUF を指定します。`--model-file` を省略すると、現在のディレクトリの `local/models/plamo-3-translate-2b-Q4_K_M.gguf` を使います。GGUF を参照できない場合は、ファイル内容が変わったら必ず変える識別子を `--model VERSION` で指定できます。

```sh
swift run soeyaku-cli extract document.pdf
swift run soeyaku-cli translate document.pdf --port 8080 --model-file /path/to/model.gguf
swift run soeyaku-cli locate document.pdf screenshot.png --pointer 700,331
```

## 実装範囲

PDF・HTML のドキュメントモードを実装しています。PDFの二段組みは座標から左段→右段の読み順に並べ、ページ上下端の繰り返すヘッダーとページ番号を本文から除きます。現在地は、ポインターの下の行とその上下の行を Vision で読み、事前に抽出した本文の3語連続と照合して決めます。同じ見出しが何度も出る場合は前後の行で区別し、それでも決まらなければ直前の現在地に近い方を選びます。

枠モード1・2の実装と、生成した台詞画面での実機確認を終えています。PDF は前進・逆スクロール・ページ飛び、手動スクロール復帰、幅変更を実機で確認しました。事前に正解を付けた20操作は段落・文とも全件一致しました。[PDFの検証記録](docs/validation/pdf-document-mode-2026-11-06.md)に採点方法と制約を記録しています。HTML の実装時は167件の全自動テストに加え、実資料98文とHTTP入力11文の翻訳・保存訳再利用、公開HTTPSの取得と翻訳を確認しました。Chromeの実機で、二段組み・同名見出し・文頭の行が一部切れた表示を含む15操作が段落・文とも一致し、訳文の手動スクロールからも復帰しました。この少数資料の確認を一般のWebサイトの正答率とは扱いません。[HTMLの検証記録](docs/validation/html-document-mode-2026-11-06.md)に採点方法と制約を記録しています。
