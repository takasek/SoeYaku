## 翻訳接続の結果

公式 chat template を使った Kikiyaku 形式の要求では、用語集の有無で「サブプロセス」「実行ファイル」が変わらなかった。日→英の「水曜日の会議は中止です。」も日本語のまま返った。これらは要求形式を再現した試験で、実字幕ではない。詳細は `baseline-results.json`。

任意のローカル変換ツール `Tools/kikiyaku_plamo.py` を加えた後、Kikiyaku の実際の `OpenAICompatSession` とモデルを使った接続試験で次を確認した。

| 条件 | 実際の出力 |
| --- | --- |
| 英→日・用語集なし | ほとんどの場合、FilePathを使用して実行ファイルへのフルパスを指定し、サブプロセスを起動します。 |
| 同じ入力・用語集あり | ほとんどの場合、FilePathを使用して実行プログラムへのフルパスを指定し、子プロセスを起動します。 |
| 次の英→日・履歴あり | 子プロセスが終了すると、終了ステータスや標準出力、その他プロセスの実行に関する情報を確認できます。 |
| 同じ接続から日→英「子プロセスを起動します。」 | Launch a subprocess. |

初回は逆方向の履歴を渡して日→英が「起動します。」になった。同方向の直近3対訳に絞った後、上表の結果になった。失敗例も `stock-client-direction-failure.json` に残した。成功結果は `stock-client-results.json`、Swift 接続試験は1件成功。これは実クライアントの接続とモデルの結果であり、収音・認識・字幕 UI の証拠ではない。

## SoeYaku の資料訳

関連資料から抽出した8文を実際の SoeYaku CLI で翻訳し、文書固有の用語集と保存訳を用意した。`subprocess` を含む説明に「子プロセス」、`standard output` を含む説明に「標準出力」が現れる。結果は `handout-guided.jsonl`、保存訳は `handout-memory.json`。

SoeYaku GUI でも「8 文・翻訳済み 8 文」と表示され、訳文窓の本文に「子プロセス」「標準出力」が現れることを確認した。文書を開く前に用意した保存訳が再利用され、追加の翻訳は実行していない。

見出し `Swift Subprocess` は「Swift 子プロセス」と訳された。モジュール名の保持まで保証する結果ではない。

## 残る確認

1. Mac のロックを解除する。動画プレーヤーを準備する画面操作がロックで止まった。録音・動画再生は未開始で、追加の音声権限もまだ許可していない。
2. 新しい Kikiyaku アプリの音声認識・システムオーディオ録音の許可を得て、36秒の公開講演だけを再生する。マイクは使わない。システム音全体が対象なので、他の音源を止めてから実施する。
3. 収音を停止し、字幕窓と保存された認識・翻訳結果を照合する。追加した OS 権限をオフへ戻す。
4. 同じ2語が実字幕と資料訳に現れた場合に、短い連携デモを完成とする。Kikiyaku への連絡は別途、宛先と内容を具体化してから承認を得る。

待機に入る前に検証用のモデルと変換サーバーを停止し、両ポートが閉じたことを管理スクリプトの終了出力で確認した。Kikiyaku の `SoeYaku WWDC demo` プロファイルと `SoeYaku Swift Subprocess` 用語集は保存済み。再開時は新しいサーバーのアドレスとモデル名へプロファイルを更新してから開始する。既存の ChatGPT.app のデバイス制御はオフのままである。
