## 保存画像での照合

Claude が取得したプレビューの4ページ目の画像を利用した。採点前に8個の本文・見出し上のポインターと2個の文書外のポインターへ正解を付けた。本文は文番号の完全一致を正解とし、特定不能も失敗として分母へ含める。文書外の正しい停止は別に数える。同じ文に複数のポインターがある小規模な確認なので、段落照合の目標9割の測定には使わない。

| 分類 | 件数 | 正しい文 | 誤った文 | 特定不能 |
| --- | ---: | ---: | ---: | ---: |
| 本文・見出し | 8 | 7 | 0 | 1 |
| 文書外 | 2 | — | 0 | 2（期待どおり） |

本文の特定不能1件は、上端のツールバーで隠れ、OCR が大きく崩した行だった。読める短い次行と見出しは照合できる。初期の保存画像評価では本文8件中5件が正しく、3件が特定不能だった。改善後も、強い本文文脈に反する行を単独で照合し直さないことを回帰テストで確認した。

正解、画像、抽出文、OCR 行、最終結果、用語集の実出力は [local/evaluations/pdf-document-mode-01a1aecd](../../local/evaluations/pdf-document-mode-01a1aecd/) に置いた。これは Git 管理外のローカル検証資料であり、通常のアプリはキャプチャ画像や OCR 行を保存しない。

## 残る受け入れ確認

訳文窓を明示的に選ぶ操作と標準の「ウインドウ」メニューを追加し、Computer Use から訳文パネルを観測できるようになった。Bento4 文書5ページ目の `From a hinted MP4 file...`（文147・段落84）を指したとき、対応する日本語が黄色で強調され、その位置へスクロールすることをスクリーンショットと下端の原文で確認した。

継続検証中、Preview の本文窓より前に共有用の補助窓（タイトル `Window`、66×20）が layer 0 に列挙される実例があった。本文窓（`Bento4_SDK_documentation.pdf`、900×1129）を選ぶように修正し、実例を回帰テストへ追加した。OCR 待ちの間に前面アプリ・本文窓・ポインターが変わった場合も結果を反映しない。

訳文窓を手動スクロールしてから同じ原文へ戻った場合の再表示と、自動表示時に key window を変えないことは AppKit の実ウインドウを使うテストで確認した。重なりを除外する判定には `isOnActiveSpace` を含め、別 Space の窓や非表示の窓は追従を妨げない。

前進・逆スクロール・ページ飛びを連続した実機操作で検証する作業は残る。現在の Computer Use が送るアプリ内入力と、アプリの実装が参照する macOS の実ポインター・前面状態が一致しない場合があった。元アプリのフォーカス維持、操作方向の切り替え、窓幅変更、手動スクロールからの復帰を一連の実機操作として確認するため、CoreGraphics を使う検証補助の利用についてユーザー判断を求めた。補助コードはローカル資料内に準備し、許可前には実行しない。

前面文書のファイル名を照合する抑止は追加したが、ファイル URL の自動検証ではない。別ディレクトリの同名 PDF は区別できないため、選択した PDF と同じファイルをプレビューで開くという従来の入力条件は維持する。厳密な URL 照合のために製品の Accessibility 権限や新たなウインドウ選択工程を追加することは、この修正の対象に含めない。

段落照合の目標9割は達成未確認として残す。二段組み、繰り返す見出し、画面端の文を含め、操作前に正解段落を付けた実機試験を行う。ここでの8ポインターの文番号採点はその代替ではない。

## 照合方式の再評価

周辺文脈だけを根拠に誤移動する指摘が、短行の救済処理でも再発したため、共通方針に従って再評価した。追加要求ではなく「本文にない行へ移動しない」という既存要件への反例だった。

| 選択肢 | 残作業と失うもの |
| --- | --- |
| 現方式で失敗理由を区別する | 文脈不足と基準行への反証を別の結果にし、文脈不足の場合だけ行単独の照合を試す。既存の3-gram照合と受け入れ範囲を保持できる。 |
| 対象を狭める | 短行や切れた文を対象外にすると既存の読書要件を失うため、採用しない。 |
| 照合方式を変更する | 全体の系列アラインメントなどへ変更するには、精度・遅延・曖昧性の評価を組み直す必要がある。現時点では採用しない。 |

最初の案を選び、元の誤移動、短行、見出し、繰り返す文脈を対象にした修正と独立再レビューを一巡行った。別箇所にも同じ文字列がある反例は特定不能を返すようになり、再レビューで追加指摘はなかった。同じ前提から問題が続く場合は、例外を足す前に方式を再検討する。
